ASTERRA DevOps assignment

Maxim Shefter · summary of the work, what did not work, and where to find everything

What I built

A small geospatial platform on AWS that one command creates in any region: ./scripts/deploy.sh <region>. A GeoJSON file dropped into a private S3 bucket triggers a container Lambda that validates it and loads it into a private PostGIS database, logging every step to CloudWatch. A public MapServer runs on ECS Fargate behind Elastic IPs and scales on requests per minute. A private GDAL + GeoPandas microservice measures every loaded file. GitHub Actions tests, versions and deploys the loader on each merge to main. The same containers also run on a local Kubernetes cluster.

How I thought about it

  • Private by default. The public subnets contain one thing: a load balancer. Private subnets have no internet route and no NAT gateway; they reach AWS APIs through VPC endpoints. Security groups reference each other instead of address ranges wherever possible.
  • No secrets to leak. RDS generates the database password and keeps it in Secrets Manager. It is not in the code or the Terraform state. The pipeline signs in with OIDC, so GitHub holds no AWS keys.
  • Managed over hand-built. Lambda for an event-driven job and Fargate for the two services mean no servers to patch and nothing to SSH into.
  • Reproducible means tested. The region is the script's only argument. A smoke test uploads real files and checks the database, the logs, the map and the closed ports after every deployment.
  • Cost. Free-plan credits shaped several choices: VPC endpoints instead of a NAT gateway, single-AZ database, smallest task sizes. All of them are variables.

What did not work

  • LocalStack. RDS, ECR and container Lambdas are outside its free tier, and a local emulator cannot prove a move between regions, so I used a real account.
  • First release failed at AWS sign-in. GitHub now issues OIDC tokens for new repositories with an immutable subject (repo:owner@id/name@id), so my role trust built from owner/name never matched. The deploy script now asks GitHub for the exact subject. I also moved the sign-in ahead of the version bump, because the failed run had used up a version number.
  • Static IP versus autoscaling. An application load balancer can count requests but has no static IP; a network load balancer has Elastic IPs but cannot count requests. I chained them: NLB in front, ALB behind.
  • Things that are global, not regional. The GitHub OIDC provider exists once per account, so a second region could not create it again. The script now owns it and removes it with the last region. IAM role names carry the region for the same reason.
  • Terraform moved blocks broke the targeted apply that creates the registries first; I renamed the resources in state instead.
  • Smaller ones. MapServer's image listens on port 80 as root and 8080 otherwise, found by testing the image locally; shellcheck failed my first CI run; my first IaC upload included a Python virtual environment.
  • RDP. I chose the non-interactive GDAL microservice over a GIS desktop, so there is no workspace to open RDP to. I would rather state that than open a port to nothing.
